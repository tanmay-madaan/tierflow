## 1. Metric Audit & Provenance

### 1.1 Inference Cost Reduction vs. Token Savings Audit
* **Observed Pre-Refinement Label:** *"Token Savings: +97.4%"*
* **Root Cause & Mathematical Audit:** The metric displayed in the overview card originates from `metrics.avg_cost_reduction`, which is computed as:
  $$\text{Cost Reduction} = \frac{\text{Baseline Cost} - \text{Routed Cost}}{\text{Baseline Cost}} \times 100$$
  This formula models the financial cost reduction between the assigned tier model rates (e.g., Gemini 3.5 Flash-Lite at \$0.075 / \$0.30 per 1M tokens) versus the baseline Always-Large model (Gemini 2.5 Pro at \$1.25 / \$5.00 per 1M tokens).
* **Correction Implemented:** **Never label cost reduction as token savings.** Token volume generated by the model is neither reduced nor intended to be reduced by ~97% (actual prompt and completion token counts remain within comparable ranges across tiers).
* **Refined Display:**
  - Card Title: **Inference Cost Reduction**
  - Metric Badge: **Projected Cost Δ** (formerly *"Token Savings"*)
  - Explanatory Subtitle: *"Pricing differential vs Always-Large ($0.075 vs $1.25/M tokens)"*
  - Data Source Tag: **Model Rate Cards**

### 1.2 Latency Comparison Audit (0.96s vs. 1.73s)
* **Observed Pre-Refinement Issue:** Empirical Gemini Flash-Lite response latencies (~0.16s – 0.96s) were compared directly against counterfactual Always-Large baselines as if both had been simultaneously executed in live real-time inference.
* **Root Cause & Technical Fact:** On Google AI Studio Free Tier, Gemini Pro models have an allocation of 0 Requests Per Day (RPD), returning immediate HTTP 429 errors. Therefore, in real inference mode, the Always-Large counterfactual request is **never actually dispatched** to the live Gemini API (to avoid rate-limit crashes and unbilled charges). The 1.73s baseline latency was derived from local simulation (Demo Mode).
* **Correction Implemented:** Real Gemini API measurements are never presented as directly equivalent to simulated or counterfactual baselines.
* **Refined Display:**
  - In Live Mode: Latency subtitle clearly states: *"Empirical latency (Baseline unmeasured in live session)"* with badge **Empirical Real**.
  - In Demo Mode: Latency subtitle states: *"vs 1.73s Always-Large (Simulated)"* with badge **Simulated P50**.

---

### 1.3 Quality Score Retention & Evaluator Audit
* **Observed Pre-Refinement Issue:** Overview displayed a quality score retention figure (e.g., ~91% or 64.5%) without citing the evaluator, methodology, or sample size.
* **Root Cause & Evaluator Provenance:**
  1. *Interactive Live Session:* In `backend/evaluation/evaluator.py`, live real-time queries lack reference ground-truth answers. The evaluator purposefully returns `overall_score: None` to prevent inventing unverified quality metrics.
  2. *Simulated Demo Mode:* Generates heuristic tier scores (Small: ~6.5/10, Large: ~8.8/10).
  3. *Benchmark v2 Research Suite ($N=200$):* Quality is rigorously measured across 200 prompts using deterministic programmatic harnesses (Python unit tests for coding, exact numerical checks for math, and reference token overlap for reasoning), yielding an empirical **7.93 / 10** for ALWAYS_SMALL.
* **Correction Implemented:**
  - Overview card subtitle now reads: *"Simulated heuristic parity (N = session count)"* in Demo Mode, or *"Unmeasured for freeform live prompts"* in Live Mode.
  - Data Source Badge explicitly indicates **Heuristic Evaluator** or **Task Evaluator**, distinguishing live session state from offline benchmark runs.

## 2. Playground Usability & Visualization Refinements

### 2.1 Three-State Pipeline Visualization (`PipelineFlow.jsx`)
Previously, pipeline stages were binary (`active` vs. low-opacity). Stages now possess three unmistakable visual states:
1. **Completed:** Solid surface (`#141E2A`), emerald border (`#34D399`/40), green `CheckCircle2` icon, and emerald status text (`#34D399`).
2. **Active / In-Flight:** Elevated surface, vibrant primary border (`#3B82F6` or pulsing selected tier color), pulsating beacon, and spinning `Loader2` during inference generation.
3. **Pending / Standby:** Dark canvas (`#0D141D`), muted border (`#1E2A39`), dim text (`#718096`), and neutral grey node dot.

### 2.2 Sample Prompt Chip Wrapping & Organization
* Replaced the horizontal single-line scrollbar with a responsive wrapping container (`flex flex-wrap gap-1.5`).
* Added domain category badges to every chip (`Factual`, `Coding`, `Math`, `Optimization`, `Systems`, `Architecture`), enabling rapid one-click testing without horizontal scrolling friction.

### 2.3 Distinct Predicted Tier vs. Assigned Provider Model
* **Routing Decision Card 1:** **Predicted Routing Tier** (ML Router classification: `SMALL`, `MEDIUM`, or `LARGE` with Softmax confidence percentage).
* **Routing Decision Card 2:** **Assigned Provider Model** (Physical endpoint: `gemini-3.5-flash-lite`, `gemini-flash-latest`, or `gemini-pro-latest`).
* **Response Viewer Header:** Explicitly states *"Generated by: gemini-3.5-flash-lite (SMALL Tier)"* to ensure users never conflate the architectural routing abstraction with the concrete model endpoint.

### 2.4 Separation of Actions Preserved
* **Predict Route:** Runs offline feature extraction and ML classification in sub-5ms with zero external API calls.
* **Run Real / Demo Inference:** Executes full model generation with complete token and latency telemetry.
